# Domain docs

This repository has one domain context.

## Before exploring

- Read `CONTEXT.md` at the repository root.
- Read ADRs under `docs/adr/` that touch the work area.
- Proceed silently if a referenced file does not exist.

## Use the glossary vocabulary

Use terms as defined in `CONTEXT.md` in issue titles, plans, tests, and implementation. Avoid synonyms that the glossary rejects.

If a needed concept is absent, reconsider whether it belongs or record the gap for `domain-modeling`.

## Flag ADR conflicts

Surface any conflict with an existing ADR instead of silently overriding it.
