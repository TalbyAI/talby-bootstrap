Mapa minimo para usar Superpowers en desarrollo

Objetivo de esta leccion: saber que skill pedir en cada fase y cual es la salida minima antes de pasar a la siguiente. No memorices todos los detalles; memoriza las puertas.

1. Ideasuperpowers:brainstorming
Convierte una intencion vaga en diseno aprobado.
2. Specsuperpowers:writing-plans
Convierte el diseno en tareas pequenas y verificables.
3. Trabajo aisladousing-git-worktrees
Evita ensuciar la rama actual antes de implementar.
4. Codigotest-driven-development
Test falla, codigo minimo, test pasa, refactor.
5. Ejecucionsubagent-driven-development
Un subagente implementa cada tarea y otros revisan spec/calidad.
6. Alternativaexecuting-plans
Ejecuta el plan inline si no quieres subagentes.
7. Revisionrequesting-code-review
Revisa con contexto exacto, no con historia de chat.
8. Publicacionverification-before-completion
Solo declaras terminado con evidencia fresca.

La idea central

Superpowers no es una lista de comandos. Es una cinta transportadora de artefactos: conversacion -> spec -> plan -> tests -> codigo -> review -> PR. Si saltas un artefacto, el siguiente agente trabaja con suposiciones.

Ejercicio rapido

Escenario: "Quiero anadir login con Google a una app existente." Todavia no hay spec ni diseno aprobado. Que skill toca primero?

Respuesta y razon

Primero superpowers:brainstorming. Aunque parezca obvio, login toca UX, seguridad, datos de usuario, errores, pruebas y alcance. La salida minima es un diseno aprobado. Luego viene writing-plans.
